הגדרת QCSC-Prefect באשכול Slurm

מדריך זה מכין את צומת ההתחברות של אשכול Slurm כמארח תהליכי העבודה של qcsc-prefect. המדריך של qcsc-prefect SQD מתחיל מהתוצאה של מדריך זה.

לאחר שתסיימו את המדריך, יהיו לכם הפריטים הבאים:

פריטהיכןתכולה
~/venv/qcsc-hostצומת ההתחברות, מארח תהליכי העבודהPrefect, חבילות qcsc-prefect והפקודה qcsc-qrmi
~/venv/qcsc-nodeצמתי החישוב, בתוך jobs של Slurmה-worker של QRMI: QRMI עם הפקודה task_runner שלו, ו-qcsc-prefect-qiskit
qrmi-runtimePrefectהבלוק שמציין את המופע וה-QPU שלכם ב-IBM Quantum®
qrmi_config.jsonצומת ההתחברות וצמתי החישובמפתח ה-API של IBM Cloud®, המופעים וה-Backends שלכם עבור QRMI

הריצו כל פקודה בטרמינל בצומת ההתחברות, אלא אם השלב אומר אחרת.

דרישות מקדימות​

  • אשכול Slurm עם OpenMPI, PMIx ותוסף QRMI SPANK, שמנהל האשכול מתקין. המדריכים הבאים מתארים את הרכיבים האלה:

    • ממשק ניהול משאבים קוונטיים (QRMI)

    • תוסף SPANK עבור QRMI

    • מדריך למשתמש של תוסף SPANK

  • ספריית בית וספריית עבודה שצומת ההתחברות וצמתי החישוב רואים באותם נתיבים מוחלטים

  • גישת HTTPS יוצאת אל GitHub, PyPI, IBM Quantum ו-Prefect Cloud מצומת ההתחברות, ואל IBM Quantum מצמתי החישוב

  • חשבון IBM Quantum Platform עם מפתח API של IBM Cloud ולפחות מופע אחד

  • חשבון Prefect Cloud, או שרת Prefect שאתם מארחים

  • Git, מהדרים של C ו-C++‎, CMake, BLAS, LAPACK ו-MPI באשכול, עבור בניית ה-solvers של המדריך

הערה

הדוגמאות משתמשות במחיצת Slurm בשם normal ובצמתי החישוב c1 ו-c2. החליפו אותם בשמות של האשכול שלכם.

שלב 1: התחברות לצומת ההתחברות​

# Run in a terminal on your computer.
ssh <user>@<login-node>

שלב 2: התקנת uv​

התקינו את מנהל החבילות uv, ובדקו את ההתקנה:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

שלב 3: הגדרת הנתיבים ויצירת ספריית העבודה​

מדריך זה והמדריכים האחרים משתמשים בשני משתני סביבה:

משתנהדוגמהמטרה
QCSC_PREFECT$HOME/qcsc-prefectה-checkout של qcsc-prefect
QCSC_WORK_DIR/shared/work/qcsc-prefectספריית העבודה של jobs ה-solver וה-jobs של QRMI

שני הנתיבים חייבים להיות באחסון שצמתי החישוב רואים באותו נתיב מוחלט. אם באשכול שלכם אין ספריית /shared, בחרו נתיב משותף אחר.

הגדירו את המשתנים וצרו את ספריית העבודה. הגדירו את המשתנים שוב בכל shell חדש לפני שאתם עוקבים אחרי מדריך:

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

כדי להגדיר את המשתנים אוטומטית בכל shell חדש, הוסיפו אותם ל-~/.bashrc:

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

שלב 4: שכפול qcsc-prefect​

שכפל את המאגר, ועבור ל-release tag, למשל v0.3.1:

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

שלב 5: יצירת סביבת ה-workflow​

צור את סביבת ה-workflow עם Python 3.12, והפעל אותה:

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

התקן את חבילות qcsc-prefect. האפשרות --no-deps שומרת על הצמדות הגרסאות המדויקות בין החבילות של ה-checkout. המדריך מתקין את ה-workflow עצמו:

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

בדוק שהפקודות זמינות:

which prefect qcsc-qrmi

הפעל את ~/venv/qcsc-host בכל shell חדש ב-login node.

שלב 6: התחברות ל-Prefect​

התחבר ל-Prefect Cloud. בחר Paste an API key, הדבק מפתח API של Prefect Cloud, ובחר את ה-workspace שלך:

prefect cloud login

בדוק את החיבור. הפלט מציג את PREFECT_API_URL ואת ה-workspace שלך:

prefect config view
אופציונלי: שימוש בשרת Prefect משלך

דלג על הערה זו אם אתה משתמש ב-Prefect Cloud. כדי להשתמש בשרת Prefect משלך במקום ב-Prefect Cloud, עקוב אחרי How to run and access a Prefect server on a Slurm login node, והגדר את כתובת השרת שלך במקום <server-host>:

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

שלב 7: שמירת האישורים של IBM Quantum​

הרץ את qcsc-qrmi login אחרי ההתחברות ל-Prefect, כי הוא שומר את הבלוק qrmi-runtime:

qcsc-qrmi login

ענה על ההנחיות:

  1. הדבק את מפתח ה-API של IBM Cloud שלך. המפתח אינו מוצג.

  2. לחץ על Enter כדי להשתמש בכל ה-instances.

  3. הזן את מספר ה-instance ברירת המחדל, 1 בדוגמה הבאה.

  4. הזן את המספר או את השם של ה-Backend ברירת המחדל, 4 (ibm_kingston) בדוגמה הבאה.

הפקודה מדפיסה גם הערה על ה-compute nodes ושורות [qrmi] עבור sqd_blocks.toml, שהדוגמה משמיטה (...). אין צורך בשורות [qrmi], כי ה-workflow קורא את ה-instance ואת ה-Backend מהבלוק qrmi-runtime.

לפקודה qcsc-qrmi יש את תתי-הפקודות הבאות:

פקודהמטרה
qcsc-qrmi loginשומרת את מפתח ה-API, את ה-instances ואת ה-Backends, ושומרת את הבלוק
qcsc-qrmi refreshמאתרת שוב את ה-instances וה-Backends עם המפתח השמור
qcsc-qrmi listמדפיסה את ה-instances וה-Backends, בלי המפתח
qcsc-qrmi checkבודקת שה-instance של הבלוק יכול להשתמש ב-Backend שלו

התקנת הקובץ ב-compute nodes​

תוסף ה-SPANK קורא את qrmi_config.json בכל compute node, מהנתיב שב- plugstack.conf, לרוב /etc/slurm/qrmi_config.json. בקש ממנהל האשכול שלך להתקין את ~/.qiskit/qrmi_config.json שלך בנתיב הזה. התקן אותו שוב אחרי כל qcsc-qrmi login או qcsc-qrmi refresh.

השאר את Session Mode של הבלוק qrmi-runtime על batch, כי תוסף ה-SPANK רוכש את ה-QPU ב-batch mode.

שלב 8: יצירת סביבת ה-compute node​

ה-worker של QRMI רץ על compute node, בסביבה משלו. צור אותה מאותו checkout. האפשרות --python משאירה את ~/venv/qcsc-host פעילה:

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

החבילה qrmi[ibm] מספקת את הפקודה task_runner. המדריך מוסיף את ה-hook של קומפילציית SQD לסביבה הזו, ומשתמש ב-~/venv/qcsc-node/bin/python בתור python_executable של sqd_blocks.toml.

בדוק את ה-instances וה-Backends השמורים. הפקודה אף פעם לא מדפיסה את המפתח:

qcsc-qrmi list
# Output

בדוק שה-instance ברירת המחדל יכול להשתמש ב-Backend ברירת המחדל:

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

בדוק ש-Slurm מריץ job על שני ה-compute nodes, גם עם PMIx:

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

בדוק את סביבת ה-compute node ואת ספריית העבודה ב-compute node. הפקודה הראשונה לא מדפיסה דבר כשהייבוא מצליח:

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"

השלבים הבאים​

המלצות

  • קרא את Size the SQD diagonalization for your HPC resources כדי לבחור את ה-nodes, ה-ranks וה-threads של jobs הפותר.

  • קרא את SQD workflow README עבור קובץ התצורה, הפותרים ופרמטרי ההרצה.

  • קרא את QRMI sampler on Slurm עבור ה-worker של QRMI והמבנה של qrmi_config.json.
