Rimay Quantum Feature Extraction - Qiskit Function של Kipu Quantum

ראה את מדריך ה-API.

הערה

Qiskit Functions הן תכונה ניסיונית הזמינה רק למשתמשי תוכנית Premium, תוכנית Flex ותוכנית On-Prem (דרך IBM Quantum Platform API) של IBM Quantum®. הן נמצאות בשלב גרסת תצוגה מקדימה ועשויות להשתנות.

סקירה כללית​

Rimay מעשירה צינורות למידת מכונה קלאסיים במאפיינים שנוצרים בחומרה קוונטית. הפונקציה מקבלת נתונים טבלאיים קלאסיים ומחזירה קבוצה של מאפיינים שעברו טרנספורמציה קוונטית. כשמערכת קוונטית מעבדת את הנתונים, היא מייצרת מאפיינים עשירים שלוכדים קשרים לא-ליניאריים בין הקלטים. אפשר להשתמש במאפיינים שנוצרו בפני עצמם, או בשילוב עם המאפיינים המקוריים שלך, כדי לאמן כל מודל קלאסי. במערכי נתונים קטנים ובינוניים, מאפיינים שעברו טרנספורמציה קוונטית יכולים לשפר את איכות החיזוי בהשוואה לקווי בסיס קלאסיים גרידא.

הפונקציה הזו נבנתה למשתמשים הבאים:

  • צוותי מדעי נתונים עם צינור למידת מכונה קיים על מערכי נתונים טבלאיים קטנים ובינוניים, שבהם איכות החיזוי הגיעה למישור. אתה מוסיף את Rimay כשלב עיבוד מקדים נוסף, בלי לבנות בעצמך שום מעגלים קוונטיים.

  • חוקרים שבוחנים שיטות קוונטיות למשימות למידת מכונה.

תיאור​

אלגוריתם חילוץ המאפיינים הקוונטי [1] משלב שני עקרונות של למידת מכונה קוונטית. הראשון הוא מפות מאפיינים קוונטיות (quantum feature maps), שמשכנות נתונים במרחב הילברט בעל ממד גבוה ולכן יוצרות ייצוגים עשירים יותר. השני הוא חישוב מאגר קוונטי (quantum reservoir computing), שמשתמש בדינמיקה של מערכת קוונטית מרובת גופים כהמרה לא ליניארית של הקלט.

Rimay מקודד את ערכי המאפיינים ואת האינפורמציה ההדדית בין המאפיינים לתוך השדות המקומיים ומקדמי הצימוד של המילטוניאן של זכוכית ספין. דינמיקה קוונטית קונטרה-אדיאבטית מובילה את המערכת אל מצבי האנרגיה הנמוכה שלה, שמכילים תערובות לא ליניאריות של המתאמים בנתוני הקלט. Rimay מחלץ את המתאמים האלה באמצעות מדידת ערכי תצפית של גוף אחד ושל שני גופים. ערכי התצפית הם המאפיינים שעברו המרה קוונטית, ואותם מזינים למודל למידת המכונה שלכם.

תהליך העבודה​

  1. עבדו את הנתונים הטבלאיים מראש כמו בלמידת מכונה קלאסית. Rimay דורש מאפיינים מספריים, אז המירו מאפיינים קטגוריאליים למספריים, למשל באמצעות OneHotEncoder של scikit-learn.

  2. חלקו את הנתונים לקבוצת אימון ולקבוצת בדיקה, והעלו את שתיהן לפונקציה, כפי שמוצג בסעיף דוגמה.

  3. Rimay משתמש בנתוני האימון כדי לבנות את ההמילטוניאן שמייצג את הנתונים. כל מאפיין מתאים ל-qubit אחד, וקבוצת האימון המלאה קובעת אילו מאפיינים, ולכן אילו qubits, מקיימים אינטראקציה. Rimay שומר את המבנה הזה כדי למפות את נתוני הבדיקה ונתוני ההסקה המאוחרים באמצעות אותו המילטוניאן.

  4. לכל דגימה, ערכי המאפיינים קובעים את השדות המקומיים של ההמילטוניאן, והאינפורמציה ההדדית בין המאפיינים קובעת את מקדמי הצימוד של המבנה משלב 3. Rimay הופך את ההתפתחות הקונטרה-אדיאבטית של ההמילטוניאן הזה למעגל דיגיטלי, ומריץ את המעגלים על ה-QPU.

  5. Rimay מודד את מחרוזות הביטים שהתקבלו, ואז מחשב את ערכי התצפית של גוף אחד ואת ערכי התצפית של שני גופים עבור qubits שמצומדים פיזית.

  6. אתם מורידים את ערכי התצפית בצורה שאפשר להזין ישירות למודל שלכם, או לשלב עם המאפיינים המקוריים.

הערה

בגלל המבנה הזה, מספר ה-qubits שהרצה צריכה שווה למספר המאפיינים, ומספר המעגלים שהיא שולחת שווה למספר הדגימות.

אחרי שהתאמתם מיפוי, אפשר למפות דרכו נתונים חדשים, למשל לצורך הסקה. Rimay אז שולף את ההמילטוניאן שיצר בזמן ההתאמה ובונה ממנו את המעגלים עבור הדגימות החדשות.

שילוב Rimay בצינור למידת המכונה שלכם​

כמו בצינור קלאסי, מתחילים בעיבוד מקדים של נתוני הגלם, למשל קידוד one-hot של המאפיינים הקטגוריאליים, ומחלקים אותם לקבוצת אימון ולקבוצת בדיקה. במקום להזין את שתי הקבוצות ישירות למודל, מזינים אותן קודם ל-Rimay, ומאמנים את המודל על המאפיינים שעברו המרה קוונטית.

מבחני ביצועים​

Kipu Quantum בדקה את Rimay על מערך הנתונים German credit מ-OpenML [2], שמסווג 1000 מבקשי אשראי כבעלי סיכון אשראי טוב או רע. יש בו 13 תכונות קטגוריאליות ושבע תכונות מספריות. קידוד one-hot של התכונות הקטגוריאליות מניב 48 מאפיינים מספריים. במבחן הושארו בצד 20% מהדגימות כקבוצת הבדיקה.

כבסיס להשוואה אומנו כמה מודלים קלאסיים על המאפיינים הקלאסיים. עם Rimay אומן יער אקראי בשתי דרכים: על המאפיינים שעברו המרה קוונטית בלבד (Random forest Q), ועל המאפיינים שעברו המרה קוונטית בשילוב המאפיינים הקלאסיים (Random forest H, עבור היברידי). הטבלה מציגה רק את היער האקראי, כי הוא הציג את הביצועים הטובים ביותר על המאפיינים שעברו המרה קוונטית.

זהירות

קבוצת הבדיקה מכילה רק 200 דגימות, ולכן חיזוי נכון של דגימה אחת נוספת משנה את הדיוק ב-0.005. קראו את ההבדלים כמגמה שדורשת אימות נוסף, ולא כהשפעה מובהקת. דיוק החיזוי יכול להיות תלוי גם ברעש שמקורו בחומרה במאפיינים שחולצו. לכן השתמשו במספר מספיק של shots כך שרעש ה-shots לא יגביל את התוצאה.

קלטים​

ה-mode קובע אילו פרמטרים הרצה צריכה. לתיאור של כל פרמטר קלט, ראו את מסמך ה-API.

קובצי קלט​

  • העלו כל קובץ באמצעות catalog.file_upload() לפני שאתם מריצים את הפונקציה.

  • העלאה מחליפה כל קובץ קודם באותו שם, גם עבור משימה ששלחתם אך עוד לא התחילה. כדי להריץ כמה משימות במקביל, תנו לקבצים של כל משימה שמות משלהם, למשל run1_x_train.csv ו-run2_x_train.csv.

  • כל קובץ הוא קובץ CSV עם שורת כותרת. כל עמודה בקובץ מאפיינים היא מאפיין אחד, וכל ערך חייב להיות מספרי.

  • y_train מכיל עמודה מספרית אחת בדיוק, עם תווית אחת לכל שורה של x_train. מפו תוויות קטגוריאליות למספרים, למשל good ו-bad ל-1 ול-0.

  • ל-x_test ול-x_inference חייבות להיות אותן עמודות כמו ל-x_train, באותו סדר.

שמרו את ה-mapping_id ואת ה-backend_name

ה-mapping_id הוא הדרך היחידה להגיע למיפוי שההתאמה שלכם יצרה, ואי אפשר לחפש או לשחזר אותו. הוא מאשר שימוש במיפוי הזה, ולכן התייחסו אליו כמו אל אישור גישה ואל תשתפו אותו. אם איבדתם אותו, תצטרכו להתאים מיפוי חדש, וזה עולה עוד הרצה על חומרה קוונטית. כמו כן שמרו את ה-backend_name של ההתאמה, כי המיפוי רץ רק על המעבד הזה.

מגבלות​

  • כל מאפיין ממופה ל-qubit אחד, ולכן במעבד חייבים להיות לפחות כמה qubits שיש מאפיינים בנתונים שלכם. אם יש לכם יותר מאפיינים מזה, צמצמו אותם קודם בטכניקת בחירת מאפיינים.

  • כל דגימה הופכת למעגל אחד, והרצה סופרת יחד דגימות אימון ובדיקה. הרצה יכולה להכיל לכל היותר 15,000 דגימות.

  • משימה אחת יכולה לבקש לכל היותר 10 מיליון הרצות, ולכן מספר הדגימות כפול shots לא יכול לעבור 10 מיליון.

  • משימה חייבת להסתיים תוך 24 שעות, כולל הזמן שהמעגלים שלה ממתינים בתור של המעבד. משימה שרצה זמן רב יותר נעצרת בלי תוצאה. במעבד עמוס, שמרו על מערכי נתונים גדולים הרחק מתחת למגבלות האלה.

פלטים​

job.result() מחזיר מילון. המאפיינים שעברו המרה קוונטית עצמם נכתבים לקובצי CSV שמורידים באמצעות catalog.file_download(). לתיאור של כל מפתח במילון, ראו את מסמך ה-API. לזמן שכל שלב הרצה לקח, ראו מטא-נתוני הרצה.

כל קובץ פלט מכיל שורה אחת לכל שורת קלט, בסדר של קובץ הקלט, ועמודה אחת לכל מאפיין שעבר המרה קוונטית. העמודות ששמותיהן מתחילים ב-corr_ הן ערכי התצפית של שני גופים. בקבצים אין עמודת תוויות. התוויות של נתוני האימון נשארות בקובץ y_train שלכם.

מטא-נתוני הרצה​

resource_usage מכיל רשומה אחת לכל שלב הרצה שההרצה עברה: "RUNNING: MAPPING", "RUNNING: POST_PROCESSING", וב-QPU בדרך כלל גם "RUNNING: WAITING_FOR_QPU". כל רשומה מכילה את CPU_TIME, זמן השעון של השלב בשניות, ואת QPU_TIME, זמן ה-QPU בשניות. ב-QPU, זמן ה-QPU ש-IBM חייבה עליו נרשם תחת "RUNNING: MAPPING", השלב שבו המעגלים רצו.

"RUNNING: WAITING_FOR_QPU" הוא הזמן שהמשימות שלכם המתינו בתור של IBM. ההרצה לוקחת את הזמן הזה מחותמות הזמן של המשימות ב-IBM, ולא סופרת אותו ב-"RUNNING: MAPPING". אם IBM לא מדווחת על חותמות הזמן האלה עבור כל משימה, הרשומה חסרה וההמתנה נכללת ב-"RUNNING: MAPPING".

IBM® מסיימת את חישוב השימוש זמן מה אחרי שמשימה מסתיימת. ההרצה ממתינה לו עד כדקה. שימוש שעדיין מחושב אחרי הזמן הזה לא נכלל ב-QPU_TIME, והשימוש הסופי מוצג ב-IBM Quantum Platform. אם ההרצה לא מצליחה לקרוא את השימוש מ-IBM, QPU_TIME הוא None.

לדוגמה:

"metadata": {
    "version": "0.3.0",
    "resource_usage": {
        "RUNNING: MAPPING": {"CPU_TIME": 12.4, "QPU_TIME": 6.0},
        "RUNNING: WAITING_FOR_QPU": {"CPU_TIME": 28.8, "QPU_TIME": 0.0},
        "RUNNING: POST_PROCESSING": {"CPU_TIME": 0.3, "QPU_TIME": 0.0},
    },
}

תחילת העבודה​

בצעו אימות באמצעות מפתח ה-API שלכם ב-IBM Quantum Platform, ובחרו את ה-Qiskit Function כך:

הערה

גדלי הפונקציה​

כל משימה רצה בגודל אחד — S, M או L. אם הגודל שצוין קטן מדי, המשימה נדחית. אם הגודל גדול מהנדרש, היא רצה על פרופיל חישוב גדול ממה שהעבודה דורשת.

הגודל של משימת Rimay תלוי במספר הדגימות שהיא ממפה: השורות של x_train ו-x_test עבור fit-transform, והשורות של x_inference עבור transform. התוויות ב-y_train לא נספרות, והרצת delete לא ממפה דגימות.

מספר הדגימות הוא הקריטריון היחיד. גודל משנה רק את פרופיל החישוב: המגבלות על מאפיינים, דגימות ו-shots זהות לכל הגדלים. S ו-M רצים על אותו פרופיל חישוב ושונים במספר הדגימות שכל אחד מכסה.

ברירת המחדל היא M, והיא משמשת כשמשימה לא מבקשת גודל. לכן משימה של יותר מ-9,999 דגימות חייבת לבקש L.

אפשר גם לקרוא את המיפוי מהפונקציה עצמה באמצעות rimay.sizes_map, ואת הגודל שבו משימה רצה כשהיא לא מבקשת גודל באמצעות rimay.default_size.

חישוב הגודל לפני השליחה​

הריצו את זה על הקלטים שלכם. זה רק קורא אותם ולא עושה דבר אחר: לא נשלחת משימה ושום דבר לא נשמר, אז אפשר לקרוא לזה כמה פעמים שרוצים.

העבירו את מערכי הנתונים עצמם, לא את שמות הקבצים, באותו סדר כמו input_file, יחד עם ה-mode של ההרצה. שלב 2 בדוגמה מראה את הקריאה.

from os import PathLike
from typing import Any, Literal, Sequence, Sized

Size = Literal["S", "M", "L"]

# Upper bounds (inclusive) in samples.
_SMALL = 2_999
_MEDIUM = 9_999

FIT_TRANSFORM, TRANSFORM, DELETE = "fit-transform", "transform", "delete"

# Which positions of input_file hold samples, per mode. The labels in
# y_train submit no circuits of their own, so they are not counted.
SAMPLE_POSITIONS = {FIT_TRANSFORM: (0, 2), TRANSFORM: (0,)}

def calculate_function_size(problem: Sequence[Sized], **kwargs: Any) -> Size:
    """Return the size ("S", "M" or "L") required to run the function."""
    metrics = _measure(problem, **kwargs)
    if _is_small(metrics):
        return "S"
    if _is_medium(metrics):
        return "M"
    return "L"

def _measure(problem: Sequence[Sized], **kwargs: Any) -> dict:
    """The samples the job submits."""
    return {"samples": count_samples(problem, kwargs.get("mode"))}

def count_samples(problem: Sequence[Sized], mode: Any) -> int:
    """Rows across the data sets of ``problem`` that carry samples."""
    if mode == DELETE:
        return 0
    if mode not in SAMPLE_POSITIONS:
        raise ValueError(f"cannot size mode {mode!r}")
    if _is_name(problem) or (
        isinstance(problem, (list, tuple))
        and any(_is_name(data) for data in problem)
    ):
        raise TypeError(
            "pass the data, not the file name: read each input_file, e.g. with "
            "pandas.read_csv, and pass the data sets in input_file order"
        )
    if not isinstance(problem, (list, tuple)):
        raise TypeError(
            "pass a list of data sets in input_file order, e.g. [x_train, y_train], "
            f"not a single {type(problem).__name__}"
        )
    return sum(
        len(problem[i]) for i in SAMPLE_POSITIONS[mode] if i < len(problem)
    )

def _is_name(value: Any) -> bool:
    """A file name or path rather than data."""
    return isinstance(value, (str, bytes, PathLike))

def _is_small(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'S'."""
    return metrics["samples"] <= _SMALL

def _is_medium(metrics: dict) -> bool:
    """Determine if the metrics fit T-size 'M'."""
    return metrics["samples"] <= _MEDIUM

4. מיפוי נתונים חדשים​

אחרי שאימנתם את המודל, מפו נתונים חדשים עם המיפוי שהותאם, למשל כדי להריץ הסקה. הדוגמה הזו ממפה את x_inference.csv, שהתא הראשון בדוגמה כתב. העבירו את ה-mapping_id שההתאמה החזירה, כדי שהשורות החדשות ימופו עם אותו מיפוי ולא עם חדש.

מיפוי נבנה עבור פריסת ה-qubits של מעבד אחד, ולכן העבירו את אותו backend_name כמו בהתאמה, שההתאמה החזירה ב-result["backend_name"]. אל תשתמשו ב-least_busy() כדי לבחור את המעבד, כי הוא עלול להחזיר מעבד אחר. Rimay דוחה כל מעבד אחר לפני ששלח משהו. גם מספר ה-shots מגיע מההתאמה.

    input_file=["x_inference.csv"],
